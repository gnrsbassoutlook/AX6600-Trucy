## 〇、一分钟理解原理（不懂原理就会踩坑）

现在是**方案 B：默认放行，只拦名单里的设备**。

```
名单里的设备 → 从机:53 → 强制转到 :5335 (AdGuard Home) → 主机 192.168.1.1    ← 被过滤
其他设备     → 从机:53 → dnsmasq 正常解析              → 主机 192.168.1.1    ← 不过滤
```

**这意味着两件事**（也是最大的风险点）：

1. **加一台设备 = 两行命令**，不需要动过滤库。
2. **没加进名单的新设备 = 完全不过滤**。孩子换个新手机接上 Wi-Fi，你不加，它就一直裸奔。

## 二、加一台设备：三步（核心操作）

```sh
adhfilter devices              # 第 0 步：看设备叫什么、IP 多少、MAC 是多少
adhfilter bind   <设备名>       # 第 1 步：绑定固定 IP（关键，别跳过）
adhfilter rename <设备名> <新名> # 第 2 步（可选但强烈建议）：改成好认的名字
adhfilter add    <设备名>       # 第 3 步：加入过滤
```

实际长这样：

```sh
$ adhfilter devices
IP               名字                 MAC                是否过滤
192.168.1.106    Kids-iPhone          f8:c3:cc:16:f2:f7  是
192.168.3.149    NOH-AN00             02:e8:0c:75:fc:a2  否

$ adhfilter bind Kids-iPhone
OK  192.168.1.106 (Kids-iPhone) 已绑定固定 IP   MAC=f8:c3:cc:16:f2:f7

$ adhfilter add Kids-iPhone
OK  192.168.1.106 (Kids-iPhone) 已加入 ADH 色情过滤
    IP锚=KidADH_192_168_1_106
    MAC锚=KidADHM_f8_c3_cc_16_f2_f7  (f8:c3:cc:16:f2:f7)
```

**「设备名」也可以用 IP**：`adhfilter add 192.168.1.106` 效果一样。

> 设备名默认是设备**自己上报**的主机名——iPhone 出厂默认就叫 `iPhone`，所以路由器上看到的也是 `iPhone`。
> 想让它们好认，就用 `adhfilter rename` 改名，见下一小节。

### 给设备改名（家里不止一台 iPhone 时必看）

**名字有两个来源，路由器侧的名字优先级更高：**

| 来源 | 怎么来的 | 谁说了算 |
|---|---|---|
| **设备自报** | 手机 DHCP 请求里带的主机名（iOS 默认就是 `iPhone`） | 在手机上改：设置 → 通用 → 关于本机 → **名称** |
| **路由器侧** | 静态绑定里的 `主机名` | `adhfilter rename`（**会覆盖设备自报的名字**） |

```sh
adhfilter rename Kids-iPhone Kids-iPhone-2      # 换名字
adhfilter rename 192.168.1.106 Kids-iPhone      # 用 IP 也一样
```

**已实测**：`rename` 执行后重启 dnsmasq，**租约文件立刻跟着变**，不需要等设备重连（2026-09-27 验证）。

**建议的命名规约**（将来设备多了不打架）：

```
Kids-iPhone      孩子的手机
Kids-MacBook     孩子的笔记本
Kids-Watch       孩子的表（走 Wi-Fi 才行）
Dad-iPhone       你自己
Mom-iPhone       家人
```

⚠️ **必须用英文/数字/连字符**。中文、空格、括号都写不进去——`rename` 会自动把它们过滤掉，
但更糟的是：**在网页版里手填中文主机名会让 dnsmasq 直接崩溃、全屋断网**（这个坑已经踩过一次）。

**同名保护**：如果两台设备都叫 `iPhone`，`adhfilter add iPhone` 会**直接报错拒绝执行**，
而不是随便挑一台：

```
!! 名字 "iPhone" 同时匹配多台设备, 请改用 IP (跑 adhfilter devices 看 IP)
```

所以家里有两台 iPhone 时，要么先各自改名，要么直接用 IP 操作。

## 三、⚠️ 必做前置：在设备上关掉「私有 Wi-Fi 地址」

**不关的话，整套方案会静默失效**——设备换 MAC 后就认不出来了。

| 设备 | 路径 |
|---|---|
| iPhone / iPad | 设置 → 无线局域网 → 点 Wi-Fi 名右边的 **ⓘ** → **私有 Wi-Fi 地址** → **关闭** |
| Mac | 系统设置 → 无线局域网 → 该网络的「详细信息」→ **私有 Wi-Fi 地址** → 关闭 |

**怎么判断关没关**（看 MAC 就能看出来）：

| MAC 开头 | 含义 |
|---|---|
| `f6:` `02:` `72:` `de:` `ce:` | **随机化 MAC** → 私有地址还开着 |
| `9c:` `dc:` `a4:` `f0:` `f8:` … | 真实网卡 MAC → 已关闭 ✅ |

原理：MAC 第一字节的第二个二进制位 = 1 表示「本地管理地址」，也就是随机生成的。

**关了之后怎么办**：MAC 变了，重跑一次
```sh
adhfilter resync <设备名>
```
（`resync` 会按当前实际 MAC 重建两条锚，并把静态绑定刷新）

> ⚠️ 别把「私有 Wi-Fi 地址」和旁边那个「**限制 IP 地址跟踪**」搞混——后者是防 Safari/邮件追踪器的，**跟过滤毫无关系**，关不关都一样。

## 四、命令全表

| 命令 | 作用 |
|---|---|
| `adhfilter devices` | 列出所有出现过租约的设备：IP / 名称 / MAC / **是否已过滤** / 是否在线 |
| `adhfilter list` | 只列被过滤的设备，并显示锚点是否完好 |
| `adhfilter bind <名\|IP>` | 绑定固定 IP（自动读 MAC 和主机名）— **不等于加入过滤** |
| `adhfilter rename <名\|IP> <新名>` | 给设备改个好认的名字（建议纯英文） |
| `adhfilter add <名\|IP>` | 加入过滤（自动建 **IP 锚 + MAC 锚** 两条） |
| `adhfilter del <名\|IP>` | 移出过滤（规则和静态绑定一起删，恢复放行） |
| `adhfilter resync <名\|IP>` | 设备**换了 MAC** 后刷新两条锚 |
| `adhfilter check` | **五项自检**，出问题先跑这个 |

### 「双锚」是什么，为什么要有两条规则

每台设备其实生成了两条防火墙规则：

```
-A zone_lan_prerouting ... -m mac --mac-source f8:c3:cc:16:f2:f7 ... ← MAC 锚
-A zone_lan_prerouting -s 192.168.1.106/32 -p tcp --dport 53 ...     ← IP 锚
```

- 静态绑定丢了、设备拿到别的 IP → **MAC 锚照样拦住它**
- 换 MAC 了 → 重新 `bind` + `resync` 即可

**已经实机验证过**：2026-09-27 孩子 iPhone 关私有地址换 MAC 后掉到了地址池的 `192.168.1.106`，
IP 锚完全匹配不上，但 MAC 锚立刻接住了它——**整个过程中过滤一刻没断**。

## 五、网页版怎么配（不想敲命令的话）

| 想做的 | LuCI 位置 |
|---|---|
| 看设备名 / IP / MAC | **状态 → 概览 → DHCP 租约** |
| 绑定固定 IP | **网络 → DHCP/DNS → 静态地址分配**（填 主机名 / MAC / IPv4 地址） |
| 加过滤规则 | **网络 → 防火墙 → 端口转发**（⚠️ **不是**「通信规则」） |

**端口转发表单怎么填**（每台设备要填两条，一条 IP 锚一条 MAC 锚）：

| 字段 | 第一条（IP 锚） | 第二条（MAC 锚） |
|---|---|---|
| 名称 | 随便，如 `Kid-121-IP` | 如 `Kid-121-MAC` |
| 协议 | `tcp udp` | `tcp udp` |
| 源区域 | `lan` | `lan` |
| **源 MAC 地址** | 留空 | `f8:c3:cc:16:f2:f7` |
| **源 IP 地址** | `192.168.1.106` | 留空 |
| 源端口 | 留空 | 留空 |
| **外部端口** | `53` | `53` |
| **内部区域** | **留空** | **留空** |
| **内部 IP 地址** | `192.168.3.1` | `192.168.3.1` |
| **内部端口** | `5335` | `5335` |

### ⚠️ 网页版的两个坑

1. **规则顺序：网页版加的规则会排到最下面，那样是没用的！**
   我实测确认过（2026-09-27）：把一条 `192.168.3.193 → :5335` 的规则**追加到末尾**（即排在
   `Force-DNS-to-Router` 之后），结果 pornhub 解析出**真实 IP `66.254.114.41`**——**完全没被拦**。
   iptables 的 nat 表**首个匹配的 DNAT 生效，后面的不作数**，所以名单规则**必须排在
   `Force-DNS-to-Router` 之上**。

   → 用命令加（`adhfilter add`）会自动排到最前面，**这是推荐做法**。
   → 非要用网页版，加完必须手动把规则拖到 `Force-DNS-to-Router` **上方**，然后验证：
   ```sh
   iptables -t nat -S | grep "dport 53" | head -6
   # KidADH_* / KidADHM_* 必须出现在 Force-DNS-to-Router 之前
   ```

2. **主机名不能带括号 / 空格 / 中文**。在「静态地址分配」里如果填了 `(未知)`、`孩子的手机` 这种名字，
   dnsmasq 会**拒绝启动**（报 `bad DHCP host name`，然后陷入崩溃循环），
   结果就是**整个从机网络的设备全部无法解析域名**（今天真的踩过这个坑，是我给演示设备绑定占位名引起的）。
   填英文数字最安全。`adhfilter bind` 已内置名字净化和失败回滚，不会再犯。

## 七、出问题怎么办

| 症状 | 原因 | 处理 |
|---|---|---|
| 设备能打开色情站 | 不在名单里 / 没绑 IP | `adhfilter devices` 看它是不是「否」，然后 `bind` + `add` |
| 加过之后又失效了 | 设备换了 MAC（私有地址没关） | `adhfilter devices` 看 MAC 变没变 → `resync` |
| `adhfilter add 名字` 报「同时匹配多台设备」 | 两台设备同名（如都叫 `iPhone`） | 用 IP 操作，或先 `adhfilter rename` 各自改名 |
| `rename` 后名字没马上变 | dnsmasq 没来得及重载 | 脚本已自动重启，跑 `adhfilter devices` 核对；仍不对跑 `adhfilter check` |
| `del` 之后设备名还停在你起的名 | 租约文件里已有的名字不会自动退回（等设备自己续约才恢复） | 不影响过滤，可以不管 |
| `adhfilter list` 显示 `BAD(IP锚丢失)` | 规则被别的东西覆盖/顺序乱了 | `adhfilter resync <设备>` |
| `check` 报 `dnsmasq 未在服务` | 静态绑定里的主机名非法，dnsmasq 崩溃循环 | 看「网络 → DHCP/DNS → 静态地址分配」，把带括号/中文/空格的**主机名**删掉或改成英文，然后重启 dnsmasq |
| **没列名单的设备全部上不了网** | 同上（dnsmasq 挂了，默认放行链路也断了） | 同上 |
| ADH 面板打不开 | ADH 没启动 | `netstat -ln \| grep 5335`；`/etc/init.d/AdGuardHome restart` 后等 60–80 秒 |

## 八、几条铁律（别做）

1. **不要**给一条规则写多个 IP。`src_ip="192.168.1.106 192.168.3.193"` 这种写法 fw3 会**静默把源地址限制丢掉**，
   规则退化成"所有 LAN 设备"——你以为只拦了孩子，其实全屋都被拽进 ADH。**一台设备一条规则。**
2. **不要**删 `Force-DNS-to-Router`（全屋强制 DNS）。删了之后孩子把 DNS 改成 8.8.8.8 就能绕过。
3. **不要**在静态地址分配里用中文/括号/空格的主机名（见第五节坑 2）。
4. **不要**给「没加进名单」的新设备"先试试再说"——方案 B 是默认放行，**新设备默认是裸奔的**。

## 九、还有一个坑：手表

**如果手表是插 SIM 卡 / eSIM 独立上网的，它根本不经过这个路由器，这套过滤对它完全无效。**
那得靠运营商的家长控制功能。用 Wi-Fi 上网的手表才管得住。
