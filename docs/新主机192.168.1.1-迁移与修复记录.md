## 一、当前拓扑

```

                  │  LAN 口

```

现场实测：`192.168.1.1` = dropbear + LuCI（就是本机）、`192.168.1.254` = 中国电信智能网关（光猫）。

## 二、「上不了网」的真正原因

**不是 ADH 的过滤库在拦，而是迁移后残留的旧 IP 把 DNS 打进了黑洞。**

改 LAN 地址只重写了一个字段，但配置里有一批**写死了 `192.168.3.1`** 的地方没跟着走，其中两条是致命的：

| 位置 | 迁移前的值 | 后果 |
|---|---|---|
| `Force-DNS-to-Router` | `dest_ip=192.168.3.1:53` | **全屋 DNS 被 DNAT 到不存在的地址 → 什么都解析不了**（这就是"根本没法上网"） |
| 两条 `KidADH*`（IP 锚 + MAC 锚） | `dest_ip=192.168.3.1:5335` | 孩子设备的 DNS 同样进黑洞 |
| IP 锚 `src_ip` / `static host .ip` | `192.168.1.106` | 规则匹配不到设备；绑定落在旧网段被 dnsmasq 忽略 |
| ADH `upstream_dns` | `192.168.1.1` | 扶正后**指向自己** → 循环 |

> 参考：路由器**自身**一直是能上网的（`ping 223.5.5.5` 通），因为出网走默认路由；所以故障现象是"路由器正常、全屋上不了网"，很容易被误判成"路由器坏了"。

## 三、我做的改动（含回滚）

| # | 改动 | 为什么 | 回滚 |
|---|---|---|---|
| 1 | 跑 `migrate-host.sh --apply`：`adhfilter` 的 `SELF`、3 处 `dest_ip`、IP 锚 `src_ip`+段名、`dhcp.KidHost*` 的 `.ip`+段名、ADH 上游 → 全部改到 `192.168.1.x` | 修掉第二节那张表 | 备份 `/root/*.premig.*` |
| 2 | 补 `firewall.KidADH_192_168_1_106.name='KidADH_192_168_1_106'` | fw3 用 **`option name`** 生成 iptables 注释；只 `uci rename` 段 ID 不改 `name`，注释仍是旧名 | 同上 |
| 3 | `AdGuardHome.AdGuardHome.redirect='none'` | ⭐ ADH 每次启动都会自动往 dnsmasq 写回 `server=127.0.0.1#5335`+`noresolv=1`，**把「只拦孩子」悄悄还原成「全屋都拦」** | `uci set AdGuardHome.AdGuardHome.redirect='dnsmasq-upstream'` |
| 4 | 删掉 `dhcp.@dnsmasq[0].resolvfile` 覆盖 | ⭐ 它被写成了 **`/tmp/resolv.conf.auto`（本固件上是个 0 字节残留文件）**，真实文件是 `/tmp/resolv.conf.d/resolv.conf.auto` → dnsmasq 没有上游 → **全屋 `REFUSED`** | 不需要回滚（默认值才对） |
| 5 | 把 ADH init 脚本里的同一个错误路径改对 | 避免下次再踩 | `/root/AdGuardHome.init.bak` |
| 6 | `network.wan`：`peerdns=0` + `dns='223.5.5.5 119.29.29.29'` | **光猫与自己同网段（都在 `192.168.1.0/24`）→ 本机路由不到 `192.168.1.254`**，不能拿它当 DNS 上游 | `uci set network.wan.peerdns=1; uci -q delete network.wan.dns` |
| 7 | `adhfilter` 升到 v7 | 修三处隐患（见下） | 旧版本无备份，功能向后兼容 |

### adhfilter v7 修了什么
1. **锚点校验不再依赖 fw3 注释名** → 直接匹配 iptables 里的 `-s <IP>/32`、`--mac-source <MAC>`。
   之前改过段名就会误报"IP锚丢失"（本次就报了假警）。
2. **`devices` 现在同时认 IP 锚和 MAC 锚**。之前孩子手机在 `.244`、绑定在 `.121`，会显示「否」——
   **明明是拦着的，却显示没拦**，会诱导你重复添加。
3. **`resync` 只清理目标设备自己的锚**。v6 会删掉**所有** MAC 锚 —— 等你把 MacBook 也加进来后，
   给手机做一次 resync 就会把 MacBook 的锚一起删掉（严重隐患）。
4. `list` 新增「当前IP」列；`check` 新增 `resolvfile` 路径检测（共六项）。

## 五、还剩什么（按重要性）

| # | 事项 | 说明 |

| 2 | **孩子的 MacBook 已接入但完全不过滤** | 在 `192.168.1.227`，MAC `72:ad:41:e4:42:a5`（首字节第二 bit=1 → **随机化 MAC**）。先在它上面关掉「私有 Wi-Fi 地址」，再 `adhfilter bind` + `add` |

## 六、常用命令

```sh
ssh root@192.168.1.1                 # 口令同 LuCI

adhfilter devices                    # 看设备名/IP/MAC/是否被过滤
adhfilter list                      # 看被过滤设备的锚点状态
adhfilter bind  <设备名>              # ① 绑定固定 IP
adhfilter add   <设备名>              # ② 加入过滤
adhfilter rename <设备名> <新名>       # 改名（纯英文，别用中文/括号/空格）
adhfilter del   <设备名>              # 移出过滤
adhfilter resync <设备名>             # 设备换 MAC 后刷新锚点
adhfilter check                     # 六项自检，出问题先跑这个

sh /usr/bin/migrate-host.sh           # 迁移脚本（默认只预览）
```

**图形界面**：LuCI → 网络 → 防火墙 → **端口转发**（DNS 改投）/ **通信规则**（放行拒绝端口）；
状态 → 概览 → DHCP 租约（看设备名）；网络 → DHCP/DNS → 静态地址分配（绑 IP）。
ADH 面板：`http://192.168.1.1:3000/login.html`（用户名 **root**，不是 admin）。
