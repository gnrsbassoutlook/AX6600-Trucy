# 副路由器（192.168.3.1）ADH 设备过滤 —— 操作说明

> 面向对象：你自己以后想给副路由器上的某台设备（比如再接一台孩子的设备）开启色情站拦截时，
> 照着做即可。**目前副路由器是"零名单"状态 —— ADH 全功能在线，但对任何设备都不过滤。**
>
> 主机（192.168.1.1）的同名工具和机制完全一样，唯一区别是网段和 `dest_ip`。
> 脚本已改成**自动读取本机 LAN IP**，所以同一份 `adhfilter` 在两台上都能直接用。

---

## 一、一分钟版本（最省事）

在副路由器上 SSH（密码同路由器），只要三条：

```sh
adhfilter devices              # 1. 找到设备，记下它的 IP
adhfilter bind 192.168.3.120   # 2. 给它固定 IP（换成上一步看到的 IP）
adhfilter add  192.168.3.120   # 3. 加入过滤
adhfilter check                # 4. 自检，应显示 == 全部正常 ==
```

完事。以后想撤掉：`adhfilter del 192.168.3.120`

> `adhfilter` 就在 `/usr/bin/adhfilter`，两台机器上都已部署（v7，md5 `f1eaf4c6e6d7eea9467e0a3def7ca865`）。
> 本地也存了一份：`AX6600/adhfilter`。

## 二、为什么"加设备"要动防火墙？（原理，看一眼就行）

ADH 本身会对**所有**查到它的请求做 93 万条黑名单判定。问题在于：
默认情况下副路由器的所有设备 DNS 都走 dnsmasq（53 端口），**根本不会碰到 ADH**。

所以要让某台设备被过滤，必须在防火墙上**把它的 53 端口重定向到 ADH 的 5335 端口**：

```
设备 → 192.168.3.1:53
        │
        ├─ 不在名单 → dnsmasq 正常解析（不经过 ADH）
        └─ 在名单   → DNAT 到 192.168.3.1:5335（ADH）→ 命中黑名单返回 0.0.0.0
```

**每台设备写两条规则（"双锚"）**：

| 锚 | 匹配条件 | 作用 |
|---|---|---|
| IP 锚 `KidADH_192_168_3_120` | `-s 192.168.3.120/32 --dport 53` | 正常情况用它 |
| MAC 锚 `KidADHM_xx_xx_...` | `--mac-source xx:xx:... --dport 53` | 设备换了 IP 也能兜住 |

两条规则**任意一条命中就生效**，所以设备换 IP、DHCP 租约过期都不会漏。

## 三、方法 A：用 `adhfilter`（推荐）

### 3.1 看有哪些设备

```sh
adhfilter devices
```

输出示例：

```
IP               名字                      MAC                是否过滤
192.168.3.120    Kids-iPad                  aa:bb:cc:dd:ee:ff  否
192.168.3.135    (未知)                     11:22:33:44:55:66  否
-- 带 * 表示: 你起的名字与设备自报的名字不同(不影响过滤)
-- 是(MAC锚) 表示: 靠 MAC 拦着, 说明它现在用的 IP 和绑定的 IP 不一样
```

### 3.2 先固定 IP（必做）

```sh
adhfilter bind 192.168.3.120
# OK  192.168.3.120 (Kids-iPad) 已绑定固定 IP   MAC=aa:bb:cc:dd:ee:ff
```

脚本会自动做三件事：写 `dhcp.KidHost_192_168_3_120`、重启 dnsmasq、**并检测 dnsmasq 有没有被搞挂**（挂了自动回滚）。

### 3.3 给它改个好认的名字（可选，强烈建议）

```sh
adhfilter rename 192.168.3.120 Kids-iPad
# OK  192.168.3.120  名字: (未知) -> Kids-iPad
```

> ⚠️ **名字只能出现字母、数字、下划线、连字符**。中文、空格、括号会被自动剔掉。
> 原因：dnsmasq 的 `dhcp-host` 名字一旦非法，**dnsmasq 会崩溃重启循环 → 全屋断网**。

### 3.4 加入过滤

```sh
adhfilter add 192.168.3.120
# OK  192.168.3.120 (Kids-iPad) 已加入 ADH 色情过滤
#     IP锚=KidADH_192_168_3_120
#     MAC锚=KidADHM_aa_bb_cc_dd_ee_ff  (aa:bb:cc:dd:ee:ff)
```

### 3.5 自检 / 查看

```sh
adhfilter check      # 五项体检
adhfilter list       # 列出名单内的设备及锚点状态
```

`check` 正常长这样：

```
--- IP 锚 ---
OK   192.168.3.120  (Kids-iPad)
--- MAC 锚 ---
OK   aa:bb:cc:dd:ee:ff
--- dnsmasq 是否在服务(未列名单设备靠它) ---
OK   53 端口正常应答
--- dnsmasq 是否已摘除 ADH 指向(应为空) ---
OK 已摘除(非名单设备默认放行)
--- dnsmasq resolvfile 路径(必须指向存在的文件) ---
OK /tmp/resolv.conf.d/resolv.conf.auto 存在
--- ADH 5335 ---
OK 监听中
== 全部正常 ==
```

### 3.6 其余子命令

| 命令 | 作用 |
|---|---|
| `adhfilter del <IP\|名>` | 移出过滤，**同时删掉静态绑定**（想保留绑定见第 6 节） |
| `adhfilter resync <IP\|名>` | 设备换了 MAC（如 iOS 关/开"私有 Wi-Fi 地址"）后，按当前 MAC 重刷锚点 |

## 四、方法 B：纯手动 uci（不用脚本时）

假设要过滤 `192.168.3.120`（MAC `aa:bb:cc:dd:ee:ff`）：

```sh
SELF=192.168.3.1          # ★ 副路由器必须是 192.168.3.1，不是 1.1
PORT=5335
IP=192.168.3.120
MAC=aa:bb:cc:dd:ee:ff

# ---- 1) 静态绑定（不做的话，设备换 IP 后 IP 锚就失效）----
uci set dhcp.KidHost_192_168_3_120=host
uci set dhcp.KidHost_192_168_3_120.name=Kids-iPad
uci set dhcp.KidHost_192_168_3_120.mac=$MAC
uci set dhcp.KidHost_192_168_3_120.ip=$IP
uci commit dhcp
/etc/init.d/dnsmasq restart

# ---- 2) IP 锚 ----
uci set firewall.KidADH_192_168_3_120=redirect
uci set firewall.KidADH_192_168_3_120.name=KidADH_192_168_3_120
uci set firewall.KidADH_192_168_3_120.src=lan
uci set firewall.KidADH_192_168_3_120.src_ip=$IP
uci set firewall.KidADH_192_168_3_120.proto='tcp udp'
uci set firewall.KidADH_192_168_3_120.src_dport=53
uci set firewall.KidADH_192_168_3_120.dest_ip=$SELF
uci set firewall.KidADH_192_168_3_120.dest_port=$PORT
uci set firewall.KidADH_192_168_3_120.target=DNAT
uci set firewall.KidADH_192_168_3_120.enabled=1

# ---- 3) MAC 锚 ----
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff=redirect
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.name=KidADHM_aa_bb_cc_dd_ee_ff
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.src=lan
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.src_mac=$MAC
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.proto='tcp udp'
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.src_dport=53
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.dest_ip=$SELF
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.dest_port=$PORT
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.target=DNAT
uci set firewall.KidADHM_aa_bb_cc_dd_ee_ff.enabled=1

# ---- 4) 生效 + 排到最前（★ 关键，见第 7 节坑 2）----
uci commit firewall
uci reorder firewall.KidADH_192_168_3_120=0
uci reorder firewall.KidADHM_aa_bb_cc_dd_ee_ff=0
/etc/init.d/firewall reload
```

## 五、验证到底有没有生效

### 5.1 看规则是否真的进了内核

```sh
iptables -t nat -S zone_lan_prerouting | grep 5335
```

应该看到 4 行（IP 锚 tcp/udp + MAC 锚 tcp/udp），且 `--to-destination 192.168.3.1:5335`：

```
-A zone_lan_prerouting -s 192.168.3.120/32 -p tcp --dport 53 ... -j DNAT --to-destination 192.168.3.1:5335
-A zone_lan_prerouting -s 192.168.3.120/32 -p udp --dport 53 ... -j DNAT --to-destination 192.168.3.1:5335
-A zone_lan_prerouting -p tcp --dport 53 -m mac --mac-source aa:bb:cc:dd:ee:ff ... -j DNAT --to-destination 192.168.3.1:5335
-A zone_lan_prerouting -p udp --dport 53 -m mac --mac-source aa:bb:cc:dd:ee:ff ... -j DNAT --to-destination 192.168.3.1:5335
```

**并且这 4 行必须出现在 `Force-DNS-to-Router` 那两行之前。**

### 5.2 从被过滤的设备上实测（最可靠）

在那台设备上（不是路由器上）执行：

```sh
nslookup pornhub.com        # 应返回 0.0.0.0
nslookup xvideos.com        # 应返回 0.0.0.0
nslookup google.com         # 应返回真实 IP（比如 142.250.x.x）
nslookup huggingface.co     # 应返回真实 IP
```

> 注意：直接在副路由器上 `nslookup pornhub.com 192.168.3.1` 测的是 **dnsmasq**，
> 走不到 DNAT 那一步，**不能**用来验证设备过滤。必须从那台设备上测。

### 5.3 看 ADH 查询日志（能确认"这台设备确实被 ADH 接管了"）

浏览器打开 **http://192.168.3.1:3000/login.html**
用户名 `root`，密码同路由器 → 左侧「查询日志」

在列表里按客户端 IP 筛，应能看到 `192.168.3.120` 的查询记录，被拦的显示为「已拦截」。
（如果日志里只有 127.0.0.1 而没有该设备 IP，说明 DNAT 没生效。）

## 六、撤销 / 换机 / 只停过滤保留绑定

```sh
# 彻底撤掉（规则 + 静态绑定一起删）
adhfilter del 192.168.3.120

# 只撤过滤、保留固定 IP 绑定（手动）
uci -q delete firewall.KidADH_192_168_3_120
uci -q delete firewall.KidADHM_aa_bb_cc_dd_ee_ff
uci commit firewall
/etc/init.d/firewall reload

# 设备换了 MAC 之后（比如 iOS 关掉再打开"私有 Wi-Fi 地址"）
adhfilter resync 192.168.3.120
```

### 换 IP 的场景

如果设备**换到了另一个 IP**（例如从 .120 变 .140），别改规则，只要：

```sh
adhfilter bind 192.168.3.140     # 先绑新 IP
adhfilter resync 192.168.3.140   # 刷新锚点（会清掉旧的）
```

## 七、五个必须记住的坑

**1. `dest_ip` 必须是 192.168.3.1（本机），不能是 192.168.1.1**
副路由器上没有主机的 ADH。如果写错了，被过滤设备的 DNS 会被转到隔壁那台机器上。
（脚本已自动用 `uci get network.lan.ipaddr` 取值，所以用 `adhfilter` 不会踩这个坑。）

**2. 规则必须 `uci reorder <段名>=0` 排到最前面**
防火墙 PREROUTING 是**首个匹配的 DNAT 生效**。`Force-DNS-to-Router` 会把 `*:53` 拉回
路由器自己的 dnsmasq；如果 KidADH 排在它后面，就永远匹配不到，**过滤静默失效**。

**3. 不要在 LuCI「端口转发」网页里加这条规则**
LuCI 新加的规则**追加到列表末尾**，也就排到了 `Force-DNS-to-Router` 后面 → 不生效。
用 `adhfilter`，或按第 4 节手动敲（含 `uci reorder`）。

**4. `dhcp-host` 的名字只能用 `[A-Za-z0-9_-]`**
中文 / 空格 / 括号 → dnsmasq 崩溃循环 → **全屋断网**。迷惑症状：`status` 显示 running，
但 53 端口没有监听。排查：`logread | grep -i dnsmasq` 找 `bad DHCP host name`。

**5. 别让孩子的设备手工改 DNS**
副路由器的代理链（ssr-plus 的 `SS_SPEC_WAN_AC`）排在防火墙 DNAT 之前。
设备若手工把 DNS 设成 8.8.8.8，TCP 的 53 会被代理链直接劫持到梯子（v2ray:1234），
**绕过 ADH**。保持设备用自动获取的 DNS（= 192.168.3.1）最稳妥。

## 九、出问题时最快的三步

```sh
adhfilter check                                   # 1. 体检，看哪一项 BAD
iptables -t nat -S zone_lan_prerouting            # 2. 看规则顺序有没有排错
logread | grep -i dnsmasq | tail -20              # 3. dnsmasq 有没有报错
```

- IP/MAC 锚 `BAD` → `adhfilter resync <IP>`
- dnsmasq 起不来 → 看第 7 节坑 4（名字非法）
- 全屋 DNS 挂了 → `uci -q delete dhcp.@dnsmasq[0].resolvfile; uci commit dhcp; /etc/init.d/dnsmasq restart`
- 实在不行 → `adhfilter del <IP>` 先恢复上网，再慢慢查
